# Модели: несколько копий одного состояния

Модель нужна, когда одна и та же логика должна работать в нескольких копиях с независимым состоянием: карточка на каждого пользователя, форма на каждый документ, счётчик на каждую вкладку. Шаблон модели описывает, как построить набор сторов, событий и эффектов. Экземпляр строится по адресу и живёт, пока у него есть владелец.

Если копия одна и владелец очевиден, модель всё равно удобна: корневое состояние приложения тоже экземпляр, и его удобно передавать вниз провайдером.

## Как использовать

### Объявить шаблон

```ts
import { computed, effect, event, model, store } from 'stm'

export const user = model((id: string) => {
  const load = effect((_: void, { deps, signal }) => deps.api.user(id, signal))
  const data = store<User | null>(null).on(load.done, (_, { result }) => result)
  const like = event()
  const likes = store(0).on(like, n => n + 1)
  const title = computed([data, likes], (u, n) => `${u ? u.name : `#${id}`} · ${n} ❤`)
  return { load, data, like, title }
})

export const app = model(() => {
  const add = event()
  const ids = store<string[]>([]).on(add, ids => [...ids, String(ids.length + 1)])
  return { add, ids }
})
```

Фабрика получает доменный ключ, если он есть, и возвращает объект с юнитами. У шаблона нет имени и состояния. Тип ключа задаётся аннотацией параметра, тип экземпляра выводится из возвращаемого объекта. Откуда берётся `deps.api`, описано в README.

### Адрес экземпляра

Экземпляр адресуется ключом типа и, если фабрика его принимает, доменным ключом. Ключ типа задаётся при создании экземпляра, а не у шаблона, поэтому из одного шаблона в одном скоупе можно построить несколько корневых экземпляров: `app` под ключами `left` и `right`.

| Экземпляр | Ключ типа | Доменный ключ | Адрес |
| --- | --- | --- | --- |
| корневой | `'root'` | нет | `root` |
| пользователь | `'user'` | `'42'` | `user/42` |
| локальный для компонента | из `useId` | нет | `«r3»` |

Один и тот же адрес с другим шаблоном даёт ошибку сразу при создании.

### Подключить в React

Экземпляр создаёт ровно один компонент, владелец. Он же отдаёт экземпляр вниз провайдером, а потребители забирают его хуком `useModel`.

```tsx
import { ModelProvider, useCreateLocalModel, useCreateModel, useEvent, useModel, useRun, useStore } from 'stm-react'

function UserTitle() {                          // потребитель
  const { title } = useModel(user)
  return <h3>{useStore(title)}</h3>
}

function UserCard({ id }: { id: string }) {     // владелец
  const m = useCreateModel(user, 'user', id)
  const ui = useCreateLocalModel(details)       // приватный экземпляр, ключ типа из useId
  const run = useRun(m.load)
  return (
    <ModelProvider value={m}>
      <UserTitle />
      <button onClick={() => run()}>Загрузить</button>
    </ModelProvider>
  )
}

function App() {
  const root = useCreateModel(app, 'root')
  return <ModelProvider value={root}>…</ModelProvider>
}
```

Второй владелец того же адреса получает ошибку. Если экземпляр нужен двум соседним поддеревьям, его создаёт общий предок и передаёт вниз провайдером, как состояние в React поднимают вверх.

### Без React

```ts
const a = scope.model(user, 'user', '1')          // получить или создать
scope.emit(a.like)
scope.get(a.title)                                // '#1 · 1 ❤'

const release = scope.claim(user, 'user', '1')    // стать владельцем
release()                                         // отпустить: удалится через unmountDelay
scope.dispose('user', '1')                        // удалить сразу

const state = scope.serialize()                   // { user: { '1': { likes: 1 } } }
const client = createScope(deps, { state })       // значения применятся при создании экземпляров
```

## Как это устроено

### Шаблон и экземпляр

`model(create)` возвращает объект `{ create }`. Экземпляр появляется, когда скоуп вызывает `create` с доменным ключом:

```ts
const a = scope.model(user, 'user', '1')  // create('1') → { load, data, like, title }
const b = scope.model(user, 'user', '2')  // create('2') → другой { load, data, like, title }
a.data !== b.data                         // разные сторы, у каждого своё значение в скоупе
```

Разница такая же, как между классом и объектом: `user` описывает, как построить набор юнитов, а `a` и `b` уже построены.

Такой способ следует из устройства ядра. Значение стора хранится в скоупе в `Map`, где ключом служит сам объект стора. Чтобы получить две независимые копии состояния, нужны два объекта стора, и фабрика их создаёт. Альтернатива, когда набор сторов один, а ключ передаётся через контекст, потребовала бы протащить ключ через `get`, `set`, `emit`, `run`, `subscribe`, кэш computed и `pending` эффектов. В выбранной схеме юниты экземпляра остаются обычными объектами и свободно сочетаются с глобальными.

Ключ типа не хранится у шаблона по той же причине, по которой у класса нет имени экземпляра: имя у определения превратило бы шаблон в синглтон, и два корневых экземпляра из одного шаблона стали бы невозможны.

### Что делает скоуп

`scope.model(m, type, key)` ищет экземпляр в реестре по адресу. Если его нет, вызывает `m.create(key)` один раз. На время вызова скоуп включает сборщик: каждый созданный в фабрике стор, событие, эффект и computed попадает в список, который хранится рядом с экземпляром. Так скоуп знает, что принадлежит экземпляру, даже если фабрика положила юниты во вложенные объекты. Если в скоуп передали `state`, значения для этого адреса применяются сразу после создания.

`scope.claim(m, type, key)` делает вызывающего владельцем и возвращает функцию `release`. Если владелец уже есть, бросает ошибку. После `release` скоуп ждёт `unmountDelay` (по умолчанию 1 секунда) и вызывает `dispose`. Если за это время экземпляр забрали снова, удаление отменяется. Задержка нужна для React StrictMode, который монтирует компонент дважды, и для смены маршрута, когда новый владелец подхватывает состояние старого.

`scope.dispose(type, key)` удаляет экземпляр из реестра и для каждого его юнита:

- удаляет значение стора и кэш computed;
- удаляет подписчиков;
- отвязывает редьюсеры стора от событий, в том числе глобальных;
- отменяет запущенные эффекты через их `AbortSignal`. Их `done`, `failed` и `aborted` уже не эмитятся.

`scope.serialize()` обходит объект каждого экземпляра, находит сторы по путям вида `form.name` и собирает значения, которые менялись. Эффекты, события и computed пропускаются. Экземпляры с ключом из `useId` попадают в результат наравне с остальными: при гидрации React выдаст те же id для тех же позиций в дереве.

### Что делают хуки и провайдер

`useCreateModel(m, type, key)` в рендере вызывает `scope.model`, а в `useEffect` вызывает `scope.claim` и отдаёт `release` как cleanup. Экземпляр живёт, пока смонтирован владелец. `useCreateLocalModel(m, key)` делает то же, подставляя `useId()` вместо ключа типа.

`ModelProvider` ничего не создаёт и не удерживает. Он спрашивает у скоупа, из какого шаблона сделан экземпляр, и кладёт в контекст копию родительской `Map` с парой «шаблон, экземпляр». Поэтому вложенные провайдеры разных моделей накапливаются, и компонент видит их все.

`useModel(m)` читает `Map` из контекста, берёт запись по объекту шаблона и возвращает её. Хук ничего не создаёт и не подписывается. Шаблон нужен ему как ключ поиска: в контексте могут лежать экземпляры нескольких моделей, например корневой и карточки внутри него. Заодно TypeScript выводит из шаблона тип экземпляра. Если провайдеры одной модели вложены друг в друга, хук вернёт экземпляр ближайшего.

Дальше с экземпляром работают обычные хуки: `useStore(m.data)` подписывается на стор в скоупе, `useEvent(m.like)` возвращает функцию, которая эмитит событие, `useRun(m.load)` запускает эффект.
