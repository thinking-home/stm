# Модели: несколько копий одного состояния

Модель нужна, когда одна и та же логика должна работать в нескольких копиях с независимым состоянием: карточка на каждого пользователя, форма на каждый документ, счётчик на каждую вкладку. Шаблон модели описывает, как построить набор сторов, событий и эффектов и как они связаны. Экземпляр строится по адресу и живёт, пока у него есть владелец.

Модель нужна и для единственной копии: сторы, эффекты и computed нельзя объявить вне фабрики, поэтому корневое состояние приложения тоже экземпляр модели. Вне фабрики можно объявлять только события, как общую шину для сигналов вроде `logout`.

## Как использовать

### Объявить шаблон

```ts
import { computed, effect, event, model, store } from 'stm'

export const user = model((id: string, ctx) => {
  const load = effect((_: void, { deps, signal }) => deps.api.user(id, signal))
  const data = store<User | null>(null)
  const like = event()
  const likes = store(0)
  const title = computed([data, likes], (u, n) => `${u ? u.name : `#${id}`} · ${n} ❤`)

  ctx.on(load.done, ({ result }) => ctx.set(data, result))
  ctx.on(like, () => ctx.set(likes, ctx.get(likes) + 1))

  return { load, data, like, title }
})
```

Фабрика получает параметры и контекст экземпляра и возвращает объект с юнитами. У шаблона нет имени и состояния. Тип параметров задаётся аннотацией, тип экземпляра выводится из возвращаемого объекта. Откуда берётся `deps.api`, описано в README.

Контекст `ctx` даёт пять методов: `get`, `set`, `emit`, `run` и `on`. Все связи внутри модели описываются через `ctx.on`: подписка на событие или стор, которая снимается при удалении экземпляра. Слушатели вызываются в порядке регистрации, вложенный `emit` выполняется синхронно. Поэтому в фабрике сначала описывают обновления состояния, потом реакции на него: слушатель-реакция увидит уже обновлённые сторы.

```ts
const form = model(({ initial }: { initial: Draft }, ctx) => {
  const change = event<Partial<Draft>>()
  const submit = event()
  const save = effect((draft: Draft, { deps, signal }) => deps.api.save(draft, signal))
  const draft = store(initial)
  const errors = store<string[]>([])

  // состояние
  ctx.on(change, patch => {
    ctx.set(draft, { ...ctx.get(draft), ...patch })
    ctx.set(errors, [])
  })

  // реакции
  ctx.on(submit, () => {
    const list = validate(ctx.get(draft))
    if (list.length) ctx.set(errors, list)
    else ctx.run(save, ctx.get(draft))
  })

  return { change, submit, draft, errors, save }
})
```

Запускать эффекты прямо в фабрике не стоит: экземпляр создаётся во время рендера, и незакоммиченный рендер оставит висящий запрос. Загрузка при маунте запускается из `useEffect` владельца.

### Параметры и адрес экземпляра

Экземпляр адресуется ключом типа и, если нужно, доменным ключом. Ключ типа задаётся при создании экземпляра, а не у шаблона, поэтому из одного шаблона в одном скоупе можно построить несколько корневых экземпляров: `app` под ключами `left` и `right`.

Параметры фабрики и доменный ключ связаны так: если параметры строка или число, они же становятся доменным ключом; если параметры объект, ключ передаётся отдельным аргументом или не передаётся вовсе.

| Вызов | Параметры фабрики | Адрес |
| --- | --- | --- |
| `useCreateModel(app, 'root')` | нет | `root` |
| `useCreateModel(user, 'user', '42')` | `'42'` | `user/42` |
| `useCreateModel(page, 'page', { id, router }, id)` | объект | `page/<id>` |
| `useCreateLocalModel(form, { initial })` | объект | `«r3»` из `useId` |

Параметры действуют только при создании, как аргумент `useState`: если владелец позже передал другие `initial`, существующий экземпляр их не заметит. Для изменений есть события. Параметры не сериализуются, при гидрации владелец передаёт их снова.

Один и тот же адрес с другим шаблоном даёт ошибку сразу при создании.

### Подключить в React

Экземпляр создаёт ровно один компонент, владелец. Он же отдаёт экземпляр вниз провайдером, а потребители забирают его хуком `useModel`.

```tsx
import { ModelProvider, useCreateLocalModel, useCreateModel, useEvent, useModel, useRun, useStore } from 'stm-react'

function UserTitle() {                                  // потребитель
  const { title } = useModel(user)
  return <h3>{useStore(title)}</h3>
}

function UserCard({ id }: { id: string }) {             // владелец
  const m = useCreateModel(user, 'user', id)
  const ui = useCreateLocalModel(details, { open: false }) // приватный экземпляр, ключ типа из useId
  const run = useRun(m.load)
  return (
    <ModelProvider value={m}>
      <UserTitle />
      <button onClick={() => run()}>Загрузить</button>
    </ModelProvider>
  )
}

function App() {
  const root = useCreateModel(app, 'root')
  return <ModelProvider value={root}>…</ModelProvider>
}
```

Второй владелец того же адреса получает ошибку. Если экземпляр нужен двум соседним поддеревьям, его создаёт общий предок и передаёт вниз провайдером, как состояние в React поднимают вверх.

### Связать модели между собой

Основной способ: владелец передаёт один экземпляр другому через параметры. Страница получает роутер, подписывается на его события и эмитит его события в ответ на действия пользователя.

```ts
const page = model(({ id, router }: { id: string; router: InstanceOf<typeof routerModel> }, ctx) => {
  const load = effect((id: string, { deps, signal }) => deps.api.page(id, signal))
  ctx.on(router.navigated, ({ route, params }) => {
    if (route === 'page' && params.id === id) ctx.run(load, id)
  })
  return { load }
})

// владелец страницы
const router = useModel(routerModel)
const page = useCreateModel(pageModel, 'page', { id, router }, id)
```

Граф зависимостей явный, в тестах вместо роутера передаётся заглушка. Порядок слушателей между моделями получается сам собой: роутер создан раньше страницы, значит его слушатели зарегистрированы раньше, и страница видит уже обновлённое состояние роутера.

Второй способ, для сигналов без адресата: событие, объявленное вне модели. На него подписываются через тот же `ctx.on`, подписка снимается вместе с экземпляром.

### Без React

```ts
const a = scope.model(user, 'user', '1')          // получить или создать
scope.emit(a.like)
scope.get(a.title)                                // '#1 · 1 ❤'

const release = scope.claim(user, 'user', '1')    // стать владельцем
release()                                         // отпустить: удалится через unmountDelay
scope.dispose('user', '1')                        // удалить сразу

const state = scope.serialize()                   // { user: { '1': { likes: 1 } } }
const client = createScope(deps, { state })       // значения применятся при создании экземпляров
```

## Как это устроено

### Шаблон и экземпляр

`model(create)` возвращает объект `{ create }`. Экземпляр появляется, когда скоуп вызывает `create` с параметрами и контекстом:

```ts
const a = scope.model(user, 'user', '1')  // create('1', ctx) → { load, data, like, title }
const b = scope.model(user, 'user', '2')  // create('2', ctx) → другой { load, data, like, title }
a.data !== b.data                         // разные сторы, у каждого своё значение в скоупе
```

Разница такая же, как между классом и объектом: `user` описывает, как построить набор юнитов, а `a` и `b` уже построены.

Такой способ следует из устройства ядра. Значение стора хранится в скоупе в `Map`, где ключом служит сам объект стора. Чтобы получить две независимые копии состояния, нужны два объекта стора, и фабрика их создаёт. Альтернатива, когда набор сторов один, а ключ передаётся через контекст, потребовала бы протащить ключ через `get`, `set`, `emit`, `run`, `subscribe`, кэш computed и `pending` эффектов.

Ключ типа не хранится у шаблона по той же причине, по которой у класса нет имени экземпляра: имя у определения превратило бы шаблон в синглтон.

### Что делает скоуп

`scope.model(m, type, params, key)` ищет экземпляр в реестре по адресу. Если его нет, создаёт контекст и вызывает `m.create(params, ctx)` один раз. На время вызова скоуп включает сборщик: каждый созданный в фабрике стор, событие, эффект и computed попадает в список, который хранится рядом с экземпляром. Подписки, сделанные через `ctx.on`, попадают в другой список. Если в скоуп передали `state`, значения для этого адреса записываются сразу после создания, без уведомления слушателей.

`scope.claim(m, type, params, key)` делает вызывающего владельцем и возвращает функцию `release`. Если владелец уже есть, бросает ошибку. После `release` скоуп ждёт `unmountDelay` (по умолчанию 1 секунда) и вызывает `dispose`. Если за это время экземпляр забрали снова, удаление отменяется. Задержка нужна для React StrictMode, который монтирует компонент дважды, и для смены маршрута, когда новый владелец подхватывает состояние старого.

`scope.dispose(type, key)` удаляет экземпляр из реестра, снимает его подписки и для каждого его юнита:

- удаляет значение стора и кэш computed;
- удаляет подписчиков;
- отменяет запущенные эффекты через их `AbortSignal`. Их `done`, `failed` и `aborted` уже не эмитятся.

`scope.serialize()` обходит объект каждого экземпляра, находит сторы по путям вида `form.name` и собирает значения, которые менялись. Эффекты, события, computed и вложенные экземпляры других моделей пропускаются. Экземпляры с ключом из `useId` попадают в результат наравне с остальными: при гидрации React выдаст те же id для тех же позиций в дереве.

### Что делают хуки и провайдер

`useCreateModel(m, type, params, key)` в рендере вызывает `scope.model`, а в `useEffect` вызывает `scope.claim` и отдаёт `release` как cleanup. Экземпляр живёт, пока смонтирован владелец. `useCreateLocalModel(m, params)` делает то же, подставляя `useId()` вместо ключа типа.

`ModelProvider` ничего не создаёт и не удерживает. Он спрашивает у скоупа, из какого шаблона сделан экземпляр, и кладёт в контекст копию родительской `Map` с парой «шаблон, экземпляр». Поэтому вложенные провайдеры разных моделей накапливаются, и компонент видит их все.

`useModel(m)` читает `Map` из контекста, берёт запись по объекту шаблона и возвращает её. Хук ничего не создаёт и не подписывается. Шаблон нужен ему как ключ поиска: в контексте могут лежать экземпляры нескольких моделей, например корневой и карточки внутри него. Заодно TypeScript выводит из шаблона тип экземпляра. Если провайдеры одной модели вложены друг в друга, хук вернёт экземпляр ближайшего.

Дальше с экземпляром работают обычные хуки: `useStore(m.data)` подписывается на стор в скоупе, `useEvent(m.like)` возвращает функцию, которая эмитит событие, `useRun(m.load)` запускает эффект.
